# 실행 순서

실제 주행에 쓰는 명령만 순서대로 정리했다. 모두 NUC에서 `~/ws/ROLAB-COSHOW-2026/scripts/day1.sh`로 실행한다(아래는 `day1.sh`로 줄여 적음). 로봇을 움직이는 명령은 운영자가 자기 터미널에서 직접 실행한다.

## 1. 준비 (전원 켤 때 한 번)

로봇을 켜고 리모컨으로 일으켜 세운 뒤, 가만히 세워 둔 채로 진행한다.

| 순서 | 명령 | 확인할 것 |
|---|---|---|
| 1 | `day1.sh xt16` | XT16 드라이버를 켜고 `/lidar_points` 약 20 Hz |
| 2 | `day1.sh light` | 내부 PC에서 신호등 YOLO 시작 |
| 3 | `day1.sh up` | FAST-LIO·브리지·경로 추종기. 끝에 `■ up: odom lio … active`. 로봇이 움직이면 안 됨(IMU 초기화) |

`up`이 `already running`으로 거부하면 다른 스택의 브리지나 FAST-LIO가 같은 ROS 도메인에 떠 있는 것이다. 그것부터 끈다.

## 2. 회차마다

로봇을 출발 표시에 놓고 실행한다. 한 바퀴를 돌면 저절로 멈춘다. 끝나면 `q`로 주행기를 닫고, 다음 회차는 `run`만 다시 실행한다.

| 경기 | 명령 |
|---|---|
| 1일차 트랙, 인코스 | `day1.sh run in v=0.8` |
| 1일차 트랙, 아웃코스 | `day1.sh run out v=0.8` |
| 미션 코스 (빨강을 받았을 때) | `day1.sh run route=rec105326_lap1 hoop=red v=0.8` |
| 미션 코스 (노랑을 받았을 때) | `day1.sh run route=rec105326_lap1 hoop=yellow v=0.8` |
| 미션 코스, 갈래를 미리 정함 (안쪽 / 바깥쪽) | `day1.sh run route=rec105326_lap1 hoop=in v=0.8` / `hoop=out` |

- `v`의 상한은 0.8이다(모터 브리지 `max_vx`). 넘게 주면 주행기가 0.8로 낮춘다.
- `in`·`out`은 1일차 트랙의 레인 선택이다. `route=`를 주면 경로 파일이 길을 정하므로 쓰지 않는다.
- 미션 코스는 녹화 105326을 시작한 출발 표시에서 출발한다. 경로 출발점에서 1 m 넘게 떨어져 있으면 출발을 거부한다.

### 주행기 흐름

1. **출발 위치 잡기:** 벽에 맞춰 위치를 찾는다. `start found: …`가 뜨고, 그 회차의 경로 그림이 `logs/day1/plan_HHMMSS.png`로 저장된다.
2. **신호등:** 초록이 0.5초 이어지고 최근 1초 안에 빨강이 없으면 출발한다. 20초가 지나도 초록을 못 잡으면 그냥 출발한다(`light_timeout=20`, 0이면 끔).
3. **속도 구간 (미션 코스):** 나머지는 `v`(0.8), 아래 두 구간만 0.4 m/s다. 구간은 경로의 `.zones.json`에 들어 있다.
   - 라바콘 밭 (출발 표시부터 오른쪽 위로 빠져나갈 때까지, 상자 x −0.8~3.75, y −3.15~−0.75): 앞보기 0.5 m, 제자리 돌기 없음
   - 지그재그 통로: 앞보기 0.3 m, 35°가 넘는 모서리는 제자리에서 돈다
   - 구간을 나오면 원래 속도로 돌아간다. ClassicWalk는 실제로 0.65 m/s 안팎까지만 나온다(명령 0.8)
4. **훌라후프 (미션 코스, `hoop=red|yellow`):** (`hoop=in|out`이면 멈추지도 보지도 않고 처음부터 그 갈래로 간다. 안쪽 = 트랙 중심에 가까운 훌라후프)
   - 15번 핀 (2.69, 1.78)에서 멈추고 아치 쪽(177°)으로 돈다.
   - 비전에 한 번 묻고, 받은 색의 훌라후프를 지나는 갈래로 이어 간다.
   - 10초 안에 답이 없으면 두 갈래 중 하나를 무작위로 골라 간다.
5. **끝:** 한 바퀴를 돈 뒤 1.2 m 더 가서 멈춘다.

### 대회 모드와 `debug=true`

기본은 대회 모드다. 달리는 중에 사람이 신호등이나 훌라후프 갈래를 고를 수 없다. 출발 전에 주는 `hoop=in|out`은 두 모드 모두 된다.

| 기능 | 대회 모드 (기본) | `debug=true` (연습·시험) |
|---|---|---|
| `g` 키 (신호 없이 출발) | 무시 | 됨 |
| `1` / `2` 키 (훌라후프 갈래) | 무시 | 됨 |
| `light=none` (신호등 안 봄) | 실행 거부 | 됨 |

시작할 때 `competition mode`, `★ DEBUG` 중 하나가 화면에 뜬다. 대회에서는 `debug=`를 붙이지 않는다.

자동 동작은 두 모드에서 같다: 신호등 초록을 20초 못 잡으면 출발(`light_timeout=20`, 0이면 끔)하고, 훌라후프 비전이 10초 안에 답하지 않으면 갈래를 무작위로 고른다.

### 키

| 키 | 언제 | 동작 |
|---|---|---|
| `스페이스` / `x` | 언제나 | 비상 정지 |
| `g` | 신호등 기다리는 동안 (`debug=true`만) | 신호 없이 바로 출발 |
| `1` | 훌라후프 보는 자리에서 기다리는 동안, 최대 10초 (`debug=true`만) | 안쪽 갈래 `rec105326_lap1` (아치 y≈1.5) |
| `2` | 위와 같음 (`debug=true`만) | 바깥쪽 갈래 `rec105326_lap2` (아치 y≈2.3) |
| `q` | 언제나 | 정지 후 주행기 종료 |

★ **규정 주의.** 규정은 수동 출발을 막고 부정출발 3회면 실격이며, 경기 중 무선 조작도 금지한다. 경기에서는 `g`·`1`·`2`를 쓰지 말고, `light_timeout`을 쓸지는 심판 규정을 확인한 뒤 정한다. 이 키들은 연습·시험용이다.

## 3. 끝낼 때

```bash
day1.sh down
```

## 문제가 생기면

| 증상 | 확인 |
|---|---|
| `scans 0`에서 멈춤(출발 위치 못 잡음) | `day1.sh xt16` — 라이다 데이터가 안 옴 |
| `motor bridge / controller_server parameters not reachable` | `up`이 안 떠 있음 |
| `★ 신호등 메시지 없음` | `day1.sh light`를 실행했는지. `day1.sh lightcheck 20`으로 로봇을 움직이지 않고 확인 |
| `robot is … from where the route was taught to start` | 출발 표시가 다름 |
| 상태 한눈에 보기 | `day1.sh status` |
| 회차별 기록 표 | `day1.sh bench` |

## 경로 손보기 (주행 전)

| 할 일 | 명령 |
|---|---|
| 지도 위에서 핀 옮기기(`s` 저장) | `day1.sh edit rec105326_lap1` |
| lap1의 공통 구간 수정을 lap2에 반영 | `day1.sh sync rec105326_lap1 rec105326_lap2` |
| 경로 목록 | `day1.sh routes` |
| 3D 지도 보기 | `scripts/view_map.sh maps/coshow_1119` |

## 콘 배치가 바뀌었을 때 (예비)

`day1.sh run` 대신 `scripts/day1_cones.sh run …`(인자 같음)을 쓴다. 콘 구간에서 옮겨진 콘을 비켜 간다. 원래 실행은 바뀌지 않는다. 자세한 내용은 [CONES.md](CONES.md)에 있다.
