# 콘 배치가 바뀌었을 때 (콘 회피 주행기)

`day1.sh run`(원래 주행기)은 그대로 두고, 그 위에 따로 얹은 예비 주행기다. 원래 주행기는 `.cones.json`을 읽지 않으므로 이 기능을 고쳐도 원래 실행은 바뀌지 않는다.

## 실행

`day1.sh up`(그리고 `xt16`, `light`)까지는 원래 순서와 같다. `run` 대신 아래 명령을 쓴다. 인자는 `day1.sh run`과 같다.

```bash
~/ws/ROLAB-COSHOW-2026/scripts/day1_cones.sh run route=rec105326_lap1 hoop=red v=0.4
```

출발 위치 잡기, 신호등, 지그재그, 훌라후프, 한 바퀴 끝은 원래 주행기와 똑같다. 다른 점은 콘 구간 상자 안에서만 생긴다.

1. `/scan`(기존 C++ 브리지가 내는 360칸 20 Hz, 바닥과 경사는 이미 걸러짐)으로 장애물 칸을 모은다.
2. 그 칸들을 코스 지도(`maps/coshow_1119`, 가르칠 때의 콘 자리)와 비교한다. 지도에 없던 칸이 옮겨진 콘이다.
3. 옮겨진 콘이 가르친 경로를 막지 않으면 원래 경로를 그대로 탄다.
4. 막으면 앞 6 m를 옆으로 비켜 가는 경로를 다시 짠다. 가르친 경로에 가장 가깝고 매끄러우며, 모든 장애물과 0.20 m 이상 떨어진 경로다. 상자 끝에서 원래 경로로 돌아온다. 비켜 가는 동안은 0.30 m/s로 줄인다.
5. 지나갈 길이 없으면 선다. 4초 동안 계속 막혀 있으면 가장 덜 닿는 길로 간다.

출발 신호를 기다리는 동안 화면에 판단이 한 번 뜬다.

- `cones at the start: N cells seen, 0 not in the map — taught route clear` → 배치 그대로
- `★ … taught route NOT clear … cones moved?` → 콘이 옮겨졌고, 비켜 갈 예정

## 콘 구간 정하기

```bash
~/ws/ROLAB-COSHOW-2026/scripts/day1_cones.sh zone rec105326_lap1 rec105326_lap2 box=0.0,-3.15,3.75,-0.75
```
```bash
~/ws/ROLAB-COSHOW-2026/scripts/day1_cones.sh show rec105326_lap1 rec105326_lap2
```

- 상자는 트랙 좌표 `[x0, y0, x1, y1]`이다. 첫 콘보다 0.5 m쯤 앞에서 시작하고 벽은 빼야 한다. 로봇은 콘 구간 상자 밖으로 비켜 가지 않는다.
- 지금 상자는 출발 직후 콘 밭이다(콘 9개, 경로 4.2 m).
- 그림은 `logs/day1/cones_<경로>.png`에 저장된다.

## 주행 뒤 확인

```bash
~/ws/ROLAB-COSHOW-2026/scripts/day1_cones.sh last
```

마지막 주행 기록(`logs/day1/cones_HHMMSS.jsonl`, 0.5초마다)에서 가장 많이 비켜 간 순간을 그림으로 보여 준다. 그림에 나오는 것: 그때 본 장애물 칸, 지도에 없던 칸(자홍색), 보낸 경로, 로봇이 간 길. 특정 시각은 `at=<초>`로 고른다. RViz에서는 `/cone/obstacles`(odom 좌표)를 보면 된다.

## 조정값 (`day1_cones.sh run … 이름=값`)

| 값 | 기본 | 뜻 |
|---|---|---|
| `cones` | true | false면 원래 주행기와 똑같다(스캔을 안 씀) |
| `cone_clear` | 0.20 | 비켜 갈 때 경로와 스캔 칸 사이 최소 거리(m) |
| `cone_min_clear` | 0.17 | 막혔을 때 한 번 더 시도하는 거리 |
| `cone_keep_min` | 0.15 | 지도에 있던 콘이라도 이보다 가까워지면 원래 경로를 버린다 |
| `cone_new_tol` | 0.12 | 지도 칸에서 이보다 먼 스캔 칸을 옮겨진 콘으로 본다 |
| `cone_map` | maps/coshow_1119 | `none`이면 보이는 칸을 모두 새 콘으로 본다 |
| `cone_dmax` | 0.90 | 원래 경로에서 옆으로 최대 몇 m까지 비켜 갈지 |
| `avoid_v` / `avoid_lookahead` | 0.30 / 0.40 | 비켜 가는 동안의 속도와 RPP 앞보기 거리 |
| `block_s` | 4.0 | 막혀서 선 뒤 가장 덜 닿는 길로 가기까지 걸리는 초 |

★ 이 콘 밭은 좁다. 지금 가르친 경로는 가장 좁은 곳에서 지도상 콘 바닥과 0.16 m 떨어져 지나간다(로봇 반폭 0.155 m). 거리 기준을 0.3 m로 잡으면 콘을 그대로 둬도 항상 '막힘'이 되므로 0.20 m로 낮췄다. 스캔은 콘 바닥보다 안쪽(링 높이의 콘 표면)을 찍기 때문에, 스캔 기준으로는 경로가 0.228 m 떨어져 있다(아래 재생 결과).

재생 중에 버그 하나를 고쳤다. 콘 구간 밖(지그재그)에서 로봇이 경로에서 12 cm 넘게 벗어나 있으면 비켜 가기 모드로 바뀌던 문제다. 그림: `logs/day1/cones_replay_inject.png`.

재생에서는 로봇이 새 경로를 따라가지 않고 녹화된 길로 간다. 그래서 가짜 콘 바로 앞에서 경로가 위쪽, 아래쪽으로 바뀌는 일(콘 2개에서 각 2번)이 있었다. 이게 실제로 흔들리는지는 아래 시뮬레이션으로 확인해야 한다.
